# Contributing

Keep changes bounded, test changed behavior, and run `make check`. Pull requests
must state outcome, risk, verification evidence, and rollback considerations.

Use a short-lived branch from `main`, keep commits focused and signed, and do not
rewrite shared branch history. Merge through an up-to-date, reviewed pull request
using the repository's approved method (squash by default); do not push directly
to `main` outside a documented administrative emergency.
